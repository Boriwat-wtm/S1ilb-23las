# Bank — สมุดบัญชีส่วนตัว แชร์ได้

สมุดบันทึกเงินหลายเล่ม แต่ละเล่มเป็นส่วนตัวจนกว่าจะเชิญคนอื่นเข้ามา
มีทั้งสมุดรายรับ–รายจ่าย และสมุดยอดหนี้ ติดตั้งบนมือถือเป็น PWA

```
React (Vercel)  ──HTTPS──▶  FastAPI (Render)  ──▶  Postgres (Neon)
                                    │
                                    └──▶  Supabase Storage (private bucket)
```

| ส่วน | ที่อยู่ | Free tier ที่ต้องเฝ้า |
|---|---|---|
| Frontend | Vercel | – |
| Backend | Render | 750 ชม./เดือน, 0.1 vCPU, 512MB, sleep หลังไม่ใช้ 15 นาที |
| Database | Neon | 0.5GB, autosuspend หลัง idle |
| รูปสลิป | Supabase Storage (private) | 1GB |

---

## โครงสร้าง

**ผู้ใช้หนึ่งคนมีได้หลายสมุด** สมุดเป็นส่วนตัว 100% จนกว่าเจ้าของจะเชิญคนอื่นด้วย username
คนที่ถูกเชิญได้สิทธิ์อย่างใดอย่างหนึ่ง:

| สิทธิ์ | ทำอะไรได้ |
|---|---|
| `owner` | ทุกอย่าง รวมถึงเชิญ/ถอดสมาชิก เปลี่ยนตั้งค่า ลบสมุด |
| `editor` | ดูและเพิ่ม/แก้/ลบรายการ แต่จัดการสมาชิกไม่ได้ |
| `viewer` | ดูอย่างเดียว |

**สมุดสองประเภทใช้ entry model เดียวกัน** เพราะเป็นคณิตศาสตร์ตัวเดียวกัน:

| ประเภท | `in` | `out` | `ยอด = Σin − Σout` |
|---|---|---|---|
| `cashflow` | รายรับ | รายจ่าย | คงเหลือ |
| `debt` | หนี้เพิ่ม | จ่ายคืน | ยอดคงค้าง |

ต่างแค่ป้ายชื่อกับว่าจะอ่านยอดรายเดือนหรือยอดสะสม — ไม่มี branch ใน write path

## การตัดสินใจที่ล็อกไว้แล้ว

**ไม่ใช่สมาชิก = 404 ไม่ใช่ 403** — 403 จะยืนยันว่า ledger id นั้นมีอยู่จริง ซึ่งพอจะไล่เดาสมุดคนอื่นได้
สมุดที่ไม่มีอยู่กับสมุดที่คุณมองไม่เห็น ต้องแยกจากกันไม่ออก

**ทุก route ที่แตะสมุดผ่าน `LedgerRead` / `LedgerWrite` / `LedgerAdmin`** — การหาสมุดกับการเช็คสิทธิ์เป็น query เดียวกัน route จึงลืมเช็คไม่ได้ ไม่ใช่ว่าลืมแล้วยังทำงานผิดๆ ได้

**`slip_ref` unique ต่อสมุด ไม่ใช่ทั้งระบบ** — ถ้า unique ทั้งระบบ 409 จะบอกใบ้ว่าสลิปที่คุณถืออยู่มีคนลงไว้แล้วในสมุดที่คุณมองไม่เห็น

**หมวดหมู่ copy เข้าสมุดแต่ละเล่ม ไม่แชร์กัน** — ไม่งั้นหมวดหมู่ที่คนหนึ่งตั้งเองจะไปโผล่ในสมุดส่วนตัวของอีกคน

**สีบอกทิศทางของเงิน ไม่ใช่ดี/แย่** — ในสมุดหนี้ "เงินเข้า" คือหนี้เพิ่ม เขียว=ดี แดง=แย่ จึงผิดตั้งแต่ต้น
`--credit` / `--debit` แปลว่า credit/debit เฉยๆ และทุกจำนวนเงินมี `+` หรือ `−` เสมอ — สีเป็นช่องทางที่สอง ไม่ใช่ช่องทางเดียว

**รูปสลิปเก็บที่ Supabase private bucket** — ไม่ใช่ใน Postgres (DB บวมชน quota) และไม่ใช่ Cloudinary (free tier เป็น public URL ไม่มี auth) เก็บแค่ object path ใน DB ออก signed URL อายุสั้นตอนขอดู
รูปถูกย่อเหลือด้านยาว 1200px + JPEG q75 ก่อนอัปโหลดเสมอ (~100KB) การ re-encode ทิ้ง EXIF/GPS ไปในตัว

**OCR ไม่เคยอยู่บน critical path** — ฟอร์มคือ source of truth เสมอ อ่านสลิปไม่ออกคือผลลัพธ์ปกติ ไม่ใช่ error: API ตอบ 200 พร้อมช่องว่าง แล้วผู้ใช้กรอกเอง `app/ocr.py` มี timeout 15 วิ และ `extract()` ไม่มีทาง raise

**QR บนสลิปไทยใช้กันลงซ้ำ ไม่ใช่ดึงยอด** — mini-QR บนสลิปโอนเก็บ *slip verification reference* (ธนาคารต้นทาง + เลขอ้างอิง) ไม่ได้เก็บจำนวนเงินหรือวันที่

**แก้พร้อมกัน = optimistic locking** — ทุกแถวมี `version` ส่ง version ที่อ่านมากลับไปตอน PUT ไม่ตรงได้ 409 พร้อมบอก version ปัจจุบัน แทนที่จะทับงานคนอื่นเงียบๆ

**signup เปิดสาธารณะ** — เพื่อให้เชิญใครก็ได้ด้วย username โดยเจ้าของไม่ต้องไปยุ่งกับรหัสผ่านของเขา
เบรกคือ rate limit ต่อ IP ใน `app/ratelimit.py` ซึ่งเก็บ counter ใน process เดียว รีเซ็ตทุกครั้งที่ deploy และแชร์ข้าม instance ไม่ได้ — Render free มี instance เดียวพอดี ข้อแลกเปลี่ยนนี้ใช้ได้ที่นี่ที่เดียว

## Deploy runbook

ลำดับสำคัญ เพราะ Render ต้องรู้โดเมน Vercel และ Vercel ต้องรู้ URL ของ Render — ไก่กับไข่ ต้องเดินสองรอบ

### 1. Neon
สร้าง project → region **Singapore** → คัดลอก **pooled connection string** (`...-pooler...`)

### 2. Supabase (ใช้แค่ Storage ไม่ได้ใช้ DB ของมัน)
สร้าง project → **Storage → New bucket** ชื่อ `slips` → **ปิด Public bucket ให้แน่ใจ**
เอา **Project URL** กับ **service_role key** (Settings → API) — service_role ข้าม RLS ได้ ห้ามหลุดไปฝั่ง frontend

### 3. สร้างตารางใน Neon (รันจากเครื่องตัวเอง)
Render free ไม่มี shell

```bash
cd backend
python -m venv .venv && .venv/Scripts/activate
pip install -r requirements.txt
DATABASE_URL="<neon-connection-string>" python -m scripts.seed --tables-only
```

ไม่ต้อง seed ผู้ใช้ — สมัครผ่านหน้าเว็บได้เลย

### 4. Render
New → **Blueprint** → เลือก repo นี้ (อ่าน `render.yaml` เอง) → ใส่ env var ที่ `sync: false`:

| key | ค่า |
|---|---|
| `DATABASE_URL` | connection string จาก Neon |
| `CORS_ORIGINS` | ใส่ `https://localhost` ไปพลางก่อน แล้วกลับมาแก้ในข้อ 6 |
| `SUPABASE_URL` | Project URL |
| `SUPABASE_SERVICE_KEY` | service_role key |

`JWT_SECRET` Render สุ่มให้เอง — Deploy เสร็จเปิด `/health` ต้องได้ `"database":"ok"`

### 5. Vercel
Import repo → **Root Directory = `frontend`** (สำคัญ) → env `VITE_API_URL` = URL ของ Render (ไม่มี `/` ปิดท้าย)

> `VITE_*` ถูก inline ตอน build ไม่ใช่ตอน run — แก้ค่าแล้วต้อง **Redeploy**

### 6. กลับไป Render
แก้ `CORS_ORIGINS` เป็นโดเมน Vercel จริง → save

> preview deployment ของ Vercel ใช้โดเมนคนละอันทุกครั้ง จะติด CORS ถ้าไม่ได้ใส่ไว้ด้วย

### 7–8. ทดสอบแล้วติดตั้ง
เปิดโดเมน Vercel บนคอม เช็ค Console ว่าไม่มี CORS error → Safari บนมือถือ → Share → **Add to Home Screen**

## Backend

```bash
cd backend
python -m venv .venv && .venv/Scripts/activate
pip install -r requirements.txt
cp .env.example .env            # เติม DATABASE_URL + JWT_SECRET

python -m scripts.seed --demo   # ผู้ใช้+สมุดตัวอย่างสำหรับ dev
uvicorn app.main:app --reload   # http://localhost:8000/docs
```

### เทสต์

```bash
python -m tests.smoke          # 178 checks — ทั้ง API บน SQLite ชั่วคราว
python -m tests.test_timeutil  # 25 checks — คณิตศาสตร์ timezone
python -m tests.test_slip_parser  # 67 checks — อ่านยอด/วันที่ พ.ศ./ผู้รับ จากข้อความสลิป
python -m tests.test_keywords     # 43 checks — ตัวกรองคำค้น (กันตารางเน่า)
```

### ทดสอบ API key

```bash
python -m scripts.check_ai                    # ทั้งสองตัว
python -m scripts.check_ai --slip slip.jpg    # ด้วยรูปสลิปจริง
```

ถ้าไม่ใส่ `--slip` มันจะวาดสลิปไทยขึ้นมาเองแล้วยิงเข้า Vision — เช็คได้ว่าคีย์ใช้ได้ request ถูกรูป และ parser แกะออก แต่**ไม่ได้บอกความแม่นในโลกจริง** เพราะรูปที่วาดคือตัวพิมพ์คมบนพื้นขาว ส่วนของจริงคือรูปถ่ายหน้าจอมือถือ ต้องรันด้วย `--slip` กับรูปจริงอย่างน้อยหนึ่งครั้งก่อนเชื่อตัวเลข

`tests/smoke.py` เน้นหนักที่ isolation: คนนอกอ่าน/เขียน/ลิสต์/ใช้ category/ขอ signed URL/จัดการสมาชิกไม่ได้ และ entry id ข้ามสมุดไม่ได้

### เปิด OCR (อ่านสลิปให้อัตโนมัติ)

โค้ดพร้อมแล้ว ขาดแค่ API key

1. สร้าง project ใน Google Cloud → เปิด **Cloud Vision API** → ต้องผูกบัตร (free tier 1,000 ครั้ง/เดือน ซึ่งเหลือเฟือสำหรับสองคน)
2. สร้าง **API key** แล้วจำกัดให้เรียกได้เฉพาะ Cloud Vision API
3. ใส่ใน env ของ Render (หรือ `backend/.env` ตอน dev):

```
OCR_PROVIDER=google
GOOGLE_VISION_API_KEY=AIza...
```

**เป็น API key ไม่ใช่ service account** — ข้ามหน้าสร้าง service account กับ IAM role ไปได้เลย
ตอนสร้างคีย์: **API restrictions** ติ๊กเฉพาะ `Cloud Vision API` · **Application restrictions** เลือก `None`
(Render free ไม่มี IP ขาออกตายตัว ล็อก IP แล้วพังตอน redeploy ส่วน referrer ใช้กับ server-to-server ไม่ได้)
สิ่งที่กันความเสียหายจริงคือ API restriction — คีย์หลุดก็เรียกได้แค่ Vision อย่างเดียว

**สถาปัตยกรรม** — `GoogleVisionProvider` ทำแค่แปลงรูปเป็นข้อความ ส่วนการตีความว่าข้อความนั้นแปลว่าอะไรอยู่ใน `app/slip_parser.py` ซึ่งเป็น pure function มีเทสต์ของตัวเอง 40 ข้อ แบ่งแบบนี้เพราะ HTTP call ทดสอบไม่ได้ถ้าไม่มี key กับสลิปจริง เลยดันตรรกะออกมาจากฝั่งนั้นให้มากที่สุด

**ไม่ต้องทำ schema แยกรายธนาคาร** — parser ยึด *คำ* ไม่ใช่ *ตำแหน่ง* ธนาคารไทยเรียกของเหมือนกันหมด ("จำนวนเงิน" / "ยอดเงิน" / "บาท" / "THB") เพราะอยู่ใต้กติกาเดียวกันและลอกกันมา ตัวที่ต่างคือคำเรียกผู้รับ ซึ่งอยู่ในลิสต์ `_PAYEE_LABELS` — ธนาคารใหม่ = เติมคำหนึ่งคำ ไม่ใช่เขียน template ใหม่

เทสต์ครอบคลุมถ้อยคำของ 7 ธนาคาร (K PLUS, SCB, BBL, KTB, TTB, GSB, หน้าจอภาษาอังกฤษ) ด้วย parser ตัวเดียวกัน

รู้จัก: ปี พ.ศ. ทั้ง 2568 และ 68, เดือนไทยย่อทั้งมีจุดและไม่มีจุด (OCR ชอบกินจุด), ชื่อผู้รับหลัง ไปยัง/ไปที่/ถึง/ผู้รับเงิน/ผู้รับโอน/บัญชีปลายทาง/To:, และ "รหัสอ้างอิง" ซึ่งเอาไปใช้เป็น `slip_ref` กันลงซ้ำ

**เวลาเจอสลิปที่อ่านผิด** อย่าเดา — `entries.ocr_raw_text` เก็บข้อความดิบที่ Vision อ่านได้ไว้ทุกแถว เปิดดูแล้วจะเห็นเลยว่าธนาคารนั้นใช้คำว่าอะไร แล้วเติมลงลิสต์

> ⚠️ **ยังไม่เคยยิงสลิปจริงผ่าน Google Vision** ตัว parser เทสต์ครบ แต่รูปแบบ request/response เขียนจากเอกสาร ต้องลองสลิปจริงสัก 5–10 ใบก่อนถึงจะเชื่อตัวเลขที่มันเติมให้ได้ และ layout ต่างกันไปตามธนาคาร

> QR บนสลิปยังไม่ได้ decode — `pyzbar` ต้องการ `libzbar0` ซึ่งลงบน Render native runtime ไม่ได้ ถ้าจะทำต้อง decode ฝั่ง browser ด้วย `BarcodeDetector`/`jsQR`

### การเดาหมวดหมู่ — สามชั้น

วัดจริงแล้ว keyword ที่ seed มาให้เดาชื่อร้านจริงถูกแค่ **36%** (`บริษัท ซีพี ออลล์ จำกัด (มหาชน)`, `After You`, `Tops Daily`, `ตัดผม` — พลาดหมด) เลยมีสามชั้นซ้อนกัน

```
พิมพ์ชื่อรายการ + โน้ต
   ↓
1. keyword ของสมุดนี้      ตรง → ใช้เลย  (0ms, ฟรี, ผลเหมือนเดิมทุกครั้ง)
   ↓ ไม่ตรง
2. tagger (Gemini)          ถาม 1 ครั้ง → ใช้คำตอบ + เขียนกลับเป็น keyword
   ↓ ปิดอยู่ / พลาด
3. ผู้ใช้เลือกเอง           → ระบบจำคำนั้นไว้ (learned)
```

**เดาจากสองแหล่ง: ชื่อรายการ + โน้ต** — สลิปให้ชื่อผู้รับซึ่งมักไร้ประโยชน์ (`บริษัท ซีพี ออลล์ จำกัด (มหาชน)` คือบริษัทแม่ ไม่ใช่มื้อกลางวัน) ส่วนโน้ตคือที่ที่คนเขียน `ผัดกะเพรา` ทั้งคู่ถูกค้นและถูกเรียนรู้ **แยกกันเป็นคนละคำ** เพราะ "ร้านลุงหนวด" กับ "ผัดกะเพรา" ควรใช้ได้ทีละอันในครั้งหน้า ไม่ใช่ต้องมาคู่กันเสมอ

**ชั้น 3 คือชั้นที่สำคัญที่สุดและไม่เสียเงินเลย** ทุกครั้งที่คุณแก้หมวดที่ระบบเดาผิดหรือเดาไม่ออก `learn_from_entry` จะดึงแก่นของชื่อรายการมาเก็บเป็นคำค้น เกิดเฉพาะตอนที่การเดา *ผิดหรือไม่มี* — ถ้าเดาถูกอยู่แล้วจะไม่เขียนซ้ำ และมันไม่มีทาง raise เพราะการลงรายการพลาดเพราะตัวเรียนรู้สะดุดนั้นแย่กว่าการไม่ได้เรียนรู้มาก

**ชั้น 2 เป็น cache-miss handler ไม่ใช่ขั้นตอนประจำ** คำตอบถูกเขียนกลับเป็น keyword ทันที ร้านเดิมจึงถูกถามครั้งเดียวตลอดกาล ค่าใช้จ่ายลดลงเรื่อยๆ จนเกือบศูนย์ เปิดใช้:

```
TAGGER_PROVIDER=gemini
GEMINI_API_KEY=AIza...
GEMINI_MODEL=gemma-4-26b-a4b-it
```

คีย์ Gemini เอาจาก **aistudio.google.com/apikey** ไม่ใช่ Cloud Console — เป็นคีย์ธรรมดา ไม่ต้องผูก service account

**เลือกโมเดลยังไง — วัดแล้ว ไม่ได้เดา** ชื่อร้านไทยที่จงใจให้ยาก 10 อัน รันโมเดลละ 3 รอบ บนคีย์จริง

| โมเดล | คะแนน 3 รอบ | วินาที/ครั้ง | RPM | RPD |
|---|---|---|---|---|
| **gemma-4-26b-a4b-it** | **10, 10, 10** | 1.71 | 30 | **14,400** |
| gemini-3.1-flash-lite | 8, 6, 8 | 1.10 | 15 | 500 |
| gemini-3.5-flash-lite | 7, 6 | 1.17 | 15 | 500 |
| gemini-3.5 / 3.6 flash | — | — | 5 | **20** |
| gemma-4-31b-it | ใช้ไม่ได้ | — | 30 | 14,400 |

**Gemma ตัวเล็กชนะทั้งสองแกน** — โควตามากกว่า 28 เท่า และเป็นตัวเดียวที่ตอบเหมือนเดิมทุกรอบ ทั้งที่ทุกตัวถูกเรียกด้วย `temperature: 0` ส่วน Flash ตัวเต็มมี **RPD แค่ 20/วัน** ใช้จริงไม่ได้ และ **Gemma 31B ตัวใหญ่กว่ากลับพัง** — ไม่รองรับ `responseSchema` เลย คืน JSON ไม่ได้สักครั้ง (ใหญ่กว่าไม่ได้แปลว่าดีกว่า)

RPM/RPD อ่านจากหน้า https://aistudio.google.com/rate-limit ของบัญชีจริง — เอกสาร Google ไม่ประกาศ

สิ่งที่ทำให้ tag ไม่ผิดคือ **`responseSchema` ที่ใส่ enum ของหมวดในสมุดนั้น** ไม่ใช่ขนาดโมเดล — constrained decoding ทำให้มันตอบเป็นหมวดอื่นนอกลิสต์ไม่ได้เลย ไม่มี "ค่าเดินทาง" โผล่มาข้าง "เดินทาง" ไม่มีคำแปลอังกฤษ ไม่มีคำอธิบายพ่วง บวก `temperature: 0` ให้ร้านเดิมได้หมวดเดิมทุกครั้ง

```bash
python -m scripts.check_ai --compare   # ลองทุกโมเดล free tier กับชุดชื่อร้านเดียวกัน
```

เทียบความแม่นกับความเร็วบนข้อมูลจริงของคุณเอง ดีกว่าเชื่อ benchmark ของคนอื่น ส่วน **RPM ของ free tier เอกสาร Google ไม่ได้ระบุ** ให้ดูที่ aistudio.google.com ของบัญชีตัวเอง

> ⚠️ `GeminiTagger` **ยังไม่เคยยิง API จริง** เขียนตาม contract ของ generateContent และ parse แบบระวังไว้แล้ว แต่ต้องลองจริงหนึ่งครั้งก่อนเชื่อ

**Tagger ห้ามแตะจำนวนเงินเด็ดขาด** — หมวดผิดเห็นได้ในหน้าสรุปและแก้แป๊บเดียว แต่ตัวเลขที่โมเดลเดาผิดมองไม่เห็นและอยู่ถาวร ยอดเงินมาจาก OCR + regex ที่คืน `null` เมื่ออ่านไม่ออกเท่านั้น

### ตัวกรองคำค้น — เหตุผลที่ปล่อยให้เขียนอัตโนมัติได้

การจับคู่เป็น **substring** แปลว่าคำกว้างคำเดียวกลืนทั้งสมุด และเพราะ tie-break คือคำที่ยาวกว่าชนะ มันจะกลืนแบบมั่นใจด้วย ทุกอย่างที่เขียนอัตโนมัติจึงผ่าน `app/keywords.py` ก่อน:

| กฎ | เพราะอะไร |
|---|---|
| สั้นกว่า 3 ตัว | ไปแมตช์ข้างในคำอื่น |
| อยู่ใน blocklist (`ร้าน` `ค่า` `บริษัท` `สาขา` ...) | อธิบายรูปแบบธุรกรรม ไม่ใช่ว่าใคร |
| ตัวเลขล้วน | เป็นยอดเงินหรือเลขบัญชี ไม่ใช่ร้าน |
| มีอยู่แล้วชี้หมวดอื่น | คำเดียวมีสองความหมายไม่ได้ ถ้าย้ายเงียบๆ = เขียนอดีตใหม่ |
| ทับกับคำของหมวดอื่น | คำยาวกว่าจะขึ้นทับคำสั้นที่อยู่ในนั้น = จัดหมวดใหม่โดยไม่ตั้งใจ |

และ **หน้า `/categories`** แสดงทุกคำพร้อมที่มา (`ตั้งต้น` / `เรียนจากคุณ` / `AI เดา` / `คุณเพิ่มเอง`) ให้ลบได้ — นี่คือเงื่อนไขที่ทำให้การเขียนอัตโนมัติปลอดภัย ถ้าไม่มีที่ให้ดู อาการจะเป็นแค่ "บางรายการเข้าหมวดผิด" โดยไม่มีอะไรชี้สาเหตุ

### Timezone

เก็บ UTC (`TIMESTAMPTZ`) แสดงผลและกรองด้วย `Asia/Bangkok`
Render กับ Neon เป็น UTC — รายการที่ลงตอนเที่ยงคืนถึงตี 7 จะตกไปเป็นวัน UTC ก่อนหน้า ซึ่งเป็นวิธีที่ dashboard กรองรายเดือนแล้วแถวหายเงียบๆ
`app/timeutil.py` คำนวณขอบเขตเป็นเวลาไทยก่อนแล้วแปลงเป็น UTC instant (ได้ใช้ index ด้วย)

**Layout** — มือถือ: header + tab bar ล่าง (รายการ / เพิ่ม / สรุป / เพิ่มเติม) · ตั้งแต่ 900px: tab bar ถูกแทนด้วย rail ซ้ายที่โชว์ทุกสมุดพร้อมยอด (recompose ไม่ใช่ย่อ)

**Breakpoint ที่ใช้จริง**

| กว้าง | เปลี่ยนอะไร |
|---|---|
| < 480px | ซ่อนชื่อผู้ใช้บน topbar (ต้องเหลือที่ให้ชื่อสมุด) |
| < 520px | แถวสมาชิก: ชื่ออยู่บรรทัดบน ปุ่มควบคุมลงมาข้างล่าง |
| < 720px | ตัวกรองยุบอยู่หลังปุ่ม "ตัวกรอง (n)" · dropdown เดือนกินเต็มบรรทัด |

## ยังไม่ได้ทำ / ต้องระวัง

- **ยังไม่ได้ยืนยัน datetime round-trip บน Postgres จริง** — SQLite แทน `TIMESTAMPTZ` ไม่ได้ (ทิ้ง offset เก็บเป็น local wall-clock text) เลข timezone เองเทสต์ครบใน `tests/test_timeutil.py` แต่ตอนต่อ Neon ครั้งแรกให้ลงรายการตอนดึกๆ (เที่ยงคืน–ตี 7) หนึ่งรายการ แล้วเช็คว่าอยู่ถูกวัน
- **ยังไม่ได้ทดสอบบนมือถือจริง** — cold start, กล้อง, Add to Home Screen
- **OCR เขียนไว้แล้วแต่ยังไม่เคยยิงสลิปจริง** — ดูหัวข้อ "เปิด OCR" ข้างล่าง
- **signup เปิดสาธารณะ** — ใครก็สมัครได้ ควรจับตา quota Neon ถ้าเริ่มมีคนแปลกหน้าเข้ามา ถ้าอยากปิด ตัด `/auth/register` แล้วสร้างผู้ใช้ผ่าน `scripts/seed.py`
- **เชิญแล้วเข้าเลย ไม่มีขั้นตอนตอบรับ** — คนถูกเชิญเห็นสมุดโผล่มาทันที (ออกเองได้)
- **ไม่มีปุ่มลบบัญชี** — ตั้งใจ ไม่ใช่ลืม รายการที่คุณลงในสมุดคนอื่นมีชื่อคุณกำกับ ลบบัญชีแล้วจะเหลือสองทาง คือรายการหายไปจากสมุดเขา หรือเหลือแถวไม่มีชื่อคนลง ทั้งคู่ไม่ควรเกิดโดยเจ้าของสมุดไม่รู้ ทางที่มีอยู่คือออกจากสมุดคนอื่นเอง แล้วลบสมุดตัวเอง
- **เปลี่ยน username ไม่ได้** — คนอื่นใช้ชื่อนี้เชิญเข้าสมุด ถ้าเปลี่ยนได้ คำเชิญที่ส่งไปแล้วจะพัง
- **ลบรายการ/ลบสมุด → ลบไฟล์สลิปแบบ best-effort** — ถ้า storage ล่มตอนนั้นจะเหลือไฟล์กำพร้า (ยอมได้ ดีกว่าลบไม่สำเร็จ)
- **เปลี่ยนประเภทสมุดทีหลังไม่ได้** — หมวดหมู่กับความหมายของ in/out ผูกกับมัน
